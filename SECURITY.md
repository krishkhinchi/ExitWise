# Security Policy and Sandbox Threat Model

## 1. Threat Model Overview

Exitwise automates the analysis, migration proposal, and sandboxed test execution of third-party dependencies and AI-generated code. Because it downloads packages from PyPI, applies diffs generated by LLMs, and executes test suites, sandboxing and security safeguards are core requirements.

### Threats Addressed
1. **API Key & Secret Leakage**: Subprocesses executing test suites or build scripts might attempt to inspect environment variables. Exitwise aggressively scrubs all API keys (`GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GITHUB_TOKEN`, AWS tokens, SSH keys) from any child process environment.
2. **Untrusted Setup Execution**: Exitwise parses `setup.py` strictly using static Python AST analysis and **never executes `setup.py`**.
3. **Runaway Execution / Denial of Service**: All child processes (smoke tests, pytest runs, resolver checks) are governed by strict timeouts (default 45s for smoke tests, 120s for full suites) and killed immediately upon timeout.
4. **Target Repository Corruption**: Exitwise never modifies the target repository directly. All scans operate on throwaway temporary workspaces or isolated working copies.
5. **AI Hallucination Execution**: AI-proposed packages are validated against PyPI and Python version constraints before installation is attempted. Unverified or non-existent packages are rejected prior to execution.
6. **Network Isolation**: Where feasible, tests execute with network disabled, allowing only loopback (`127.0.0.1` / `localhost`) networking for repos like LinkWatch that spin up local test servers.

## 2. Environment Scrubbing Policy

When creating a child environment for baseline or candidate execution, the following environment variables are explicitly stripped:
- `GEMINI_API_KEY`, `GOOGLE_API_KEY`
- `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`
- `GITHUB_TOKEN`, `GH_TOKEN`
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`
- `PYPI_PASSWORD`, `TWINE_PASSWORD`, `TWINE_USERNAME`
- Any variable matching regex `(?i)(api[_-]?key|secret|token|password|auth|credential)`

## 3. Reporting Security Vulnerabilities

If you discover a security vulnerability in Exitwise, please open a private security advisory on GitHub or email the maintainers directly. Do not file public issues for active vulnerabilities.
